# Функциональная спецификация
## Сервис автоматического составления расписания занятий

## 1. Функциональные требования

### 1.1. Учётные записи

| Идентификатор | Требование |
|---|---|
| F_Auth_1 | Пользователь может зарегистрироваться по адресу электронной почты и паролю. |
| F_Auth_2 | Пароль при регистрации должен содержать от 6 до 20 символов включительно. |
| F_Auth_3 | Система не допускает регистрацию двух учётных записей с одинаковым адресом электронной почты. |
| F_Auth_4 | Пользователь может войти в систему по адресу электронной почты и паролю. |
| F_Auth_5 | При неверных данных авторизации система отказывает во входе и сообщает об ошибке. |
| F_Auth_6 | Пользователь может восстановить пароль по электронной почте; новый пароль также должен содержать от 6 до 20 символов включительно. |
| F_Auth_7 | Пользователь имеет доступ только к собственным проектам расписаний. |

### 1.2. Проекты расписаний

| Идентификатор | Требование |
|---|---|
| F_Project_1 | Пользователь может создать новый проект только при указании непустого имени проекта. |
| F_Project_2 | Пользователь может сохранять, открывать и удалять собственные проекты расписаний. |
| F_Project_3 | Один пользователь может хранить несколько проектов. |
| F_Project_4 | При повторном открытии проекта система восстанавливает сохранённые исходные данные, ограничения, настройки оптимизации и расписания. |

### 1.3. Исходные данные

| Идентификатор | Требование |
|---|---|
| F_Data_1 | Пользователь может задавать для нечётной и чётной недели произвольные наборы используемых дней. |
| F_Data_2 | Пользователь может выбрать режим начала занятий: только в начале часа или с заданным минимальным временным шагом. |
| F_Data_3 | Пользователь может выбрать единую длительность всех занятий или индивидуальную длительность для каждого элемента учебной нагрузки. |
| F_Data_4 | Пользователь может добавить преподавателя при обязательном указании ФИО, хотя бы одной комбинации дисциплины и типа занятия, которую преподаватель имеет право вести, а также хотя бы одного доступного дня и временного интервала. Предпочтительные дни и интервалы работы являются необязательными. |
| F_Data_5 | Пользователь может изменять и удалять преподавателей. |
| F_Data_6 | Одну и ту же комбинацию дисциплины и типа занятия можно связать с несколькими преподавателями. |
| F_Data_7 | Пользователь может добавлять, изменять и удалять аудитории с указанием номера или названия, вместимости, типа, доступных дней и времени. |
| F_Data_8 | Система поддерживает лекционные, практические универсальные, практические специализированные и лабораторные аудитории. |
| F_Data_9 | Для специализированных и лабораторных аудиторий пользователь может задавать допустимые дисциплины и виды занятий. |
| F_Data_10 | Пользователь может добавлять, изменять и удалять учебные группы с указанием названия и количества студентов. |
| F_Data_11 | Пользователь может разделить учебную группу на две или более подгруппы с указанием названия и количества студентов каждой подгруппы. |
| F_Data_12 | Суммарное количество студентов во всех подгруппах одной группы не должно превышать количество студентов основной группы. |
| F_Data_13 | Пользователь может изменять и удалять подгруппы. |
| F_Data_14 | Пользователь может вручную объединять существующие группы в потоки и изменять состав потоков. |
| F_Data_15 | Система не формирует потоки автоматически. |
| F_Data_16 | Пользователь может задавать учебную нагрузку для группы, подгруппы или потока, указывая дисциплину, тип занятия, формат занятия, количество занятий за двухнедельный цикл и, при необходимости, индивидуальную длительность. |
| F_Data_17 | Для элемента учебной нагрузки пользователь выбирает формат занятия: очный или дистанционный. |
| F_Data_18 | Если дополнительные ограничения отсутствуют, система может свободно распределять занятия между двумя неделями и размещать несколько одинаковых занятий подряд в один день. |

> **Комбинация дисциплины и типа занятия** — конкретная пара значений «дисциплина + тип занятия». Например: «Физика + практика», «Физика + лабораторная работа» и «Математика + лекция» являются тремя различными комбинациями.

### 1.4. Предпочтения преподавателей

| Идентификатор | Требование |
|---|---|
| F_Pref_1 | Для преподавателя пользователь может задать один или несколько предпочтительных дней и временных интервалов работы. |
| F_Pref_2 | Предпочтения преподавателя являются необязательными и не влияют на допустимость расписания. |
| F_Pref_3 | Занятие считается соответствующим предпочтению преподавателя, если оно полностью находится в одном из заданных преподавателем предпочтительных временных интервалов соответствующего дня. |
| F_Pref_4 | При выбранном критерии учёта предпочтений система должна предпочитать расписание с большим количеством назначений преподавателей, соответствующих их предпочтительным интервалам. |
| F_Pref_5 | Если одно лабораторное занятие ведут несколько преподавателей, соответствие предпочтениям оценивается отдельно для каждого назначенного преподавателя. |

### 1.5. Обязательные ограничения расписания

| Идентификатор | Требование |
|---|---|
| F_Rule_1 | Система размещает занятие только в интервале, в котором одновременно доступны назначенный преподаватель и все участвующие группы или подгруппы. |
| F_Rule_2 | Для очного занятия система дополнительно требует доступность назначенной аудитории в течение всей длительности занятия. |
| F_Rule_3 | Назначенный преподаватель должен иметь право вести соответствующие дисциплину и тип занятия. |
| F_Rule_4 | Для очного занятия тип, специализация и вместимость аудитории должны соответствовать занятию и числу участвующих студентов. |
| F_Rule_5 | Для дистанционного занятия аудитория не назначается; ограничения вместимости, типа, специализации и доступности аудитории к такому занятию не применяются. |
| F_Rule_6 | Два разных занятия одной группы не могут пересекаться по времени. |
| F_Rule_7 | Два разных занятия одной подгруппы не могут пересекаться по времени. |
| F_Rule_8 | Разные подгруппы одной группы могут одновременно посещать разные занятия. |
| F_Rule_9 | Занятие всей группы не может пересекаться по времени с занятием любой подгруппы этой группы. |
| F_Rule_10 | Один преподаватель не может одновременно вести два разных занятия. |
| F_Rule_11 | Лекционное или практическое занятие ведёт один преподаватель. |
| F_Rule_12 | Лабораторное занятие могут одновременно вести несколько преподавателей; для очной лабораторной работы они проводят занятие в одной лабораторной аудитории. |
| F_Rule_13 | Допустимое расписание должно полностью покрывать заданную учебную нагрузку за двухнедельный цикл. |

### 1.6. Дополнительные ограничения

| Идентификатор | Требование |
|---|---|
| F_Extra_1 | Пользователь может задавать минимально допустимое время начала и максимально допустимое время окончания занятий. |
| F_Extra_2 | Пользователь может ограничивать проведение выбранных занятий заданными днями или временными диапазонами. |
| F_Extra_3 | Пользователь может требовать проведение выбранного вида занятия на каждой неделе двухнедельного цикла. |
| F_Extra_4 | Пользователь может задавать требование о последовательном проведении двух занятий либо запрет их последовательного проведения. |
| F_Extra_5 | Пользователь может задавать минимальный временной интервал между двумя занятиями. |
| F_Extra_6 | Пользователь может задавать порядок проведения двух занятий: одно должно быть раньше другого. |
| F_Extra_7 | Пользователь может зафиксировать выбранное занятие на конкретный день. |

### 1.7. Построение и оптимизация

| Идентификатор | Требование |
|---|---|
| F_Gen_1 | Пользователь может выбрать один или несколько критериев оптимизации и задать их порядок приоритетов. |
| F_Gen_2 | Система поддерживает критерии: минимизация окон у студентов, минимизация окон у преподавателей, выполнение предпочтений преподавателей, равномерность нагрузки, минимизация ранних и поздних занятий. |
| F_Gen_3 | Критерии применяются по приоритету: следующий критерий учитывается только при равенстве вариантов по всем более приоритетным критериям. |
| F_Gen_4 | Пользователь может запросить один оптимальный вариант или `TOP-N` лучших допустимых вариантов. |
| F_Gen_5 | В режиме `TOP-N` система возвращает не более `N` расписаний в порядке от лучшего к худшему по заданным пользователем критериям. |
| F_Gen_6 | Если несколько расписаний имеют одинаковую оптимальность по всем выбранным пользователем критериям, их взаимный порядок определяется порядком получения вариантов в процессе расчёта. |
| F_Gen_7 | В режиме одного оптимального варианта при наличии нескольких равноценных вариантов система возвращает первый вариант, полученный в процессе расчёта. |
| F_Gen_8 | В режиме `TOP-N`, если число равноценных вариантов превышает оставшееся количество мест в выдаче, система возвращает первые рассчитанные варианты до заполнения `N` мест. |
| F_Gen_9 | Во время построения система отображает состояние расчёта. |
| F_Gen_10 | Пользователь может отменить выполняющийся расчёт. |
| F_Gen_11 | Если допустимое расписание не найдено, система сообщает об отсутствии решения и, если это определено в ходе расчёта, показывает неразмещённые занятия и конфликтующие ограничения. |
| F_Gen_12 | При превышении установленного предельного размера входных данных система не начинает построение и сообщает причину отказа. |

### 1.8. Просмотр и редактирование расписания

| Идентификатор | Требование |
|---|---|
| F_Edit_1 | Пользователь может просматривать отдельно нечётную и чётную недели расписания. |
| F_Edit_2 | Для каждого занятия отображаются день, время, группа, подгруппа или поток, дисциплина, тип занятия, формат занятия, преподаватель или преподаватели и, для очного занятия, аудитория. |
| F_Edit_3 | В режиме `TOP-N` пользователь может переключаться между полученными вариантами. |
| F_Edit_4 | Пользователь может вручную изменить день, время, формат, аудиторию очного занятия и назначенных преподавателей. |
| F_Edit_5 | После ручного изменения система повторно проверяет расписание и отображает обнаруженные конфликты с указанием причины. |
| F_Edit_6 | Конфликтное расписание можно сохранить. |
| F_Edit_7 | Пользователь может зафиксировать новое время или день занятия и запустить автоматическую корректировку остальных занятий с минимизацией дополнительных изменений. |

### 1.9. Работа с существующим расписанием

| Идентификатор | Требование |
|---|---|
| F_Existing_1 | Пользователь может загрузить существующее расписание и просматривать или редактировать его без полного набора исходных данных. |
| F_Existing_2 | Система выполняет только те проверки загруженного расписания, для которых присутствуют необходимые исходные данные. |
| F_Existing_3 | При наличии необходимых данных система проверяет загруженное расписание на нарушения обязательных ограничений; если обнаружено хотя бы одно противоречие, система выдаёт ошибку и перечисляет найденные противоречия. |
| F_Existing_4 | Ошибка проверки существующего расписания не удаляет загруженное расписание и не блокирует его последующее редактирование. |
| F_Existing_5 | Пользователь может выполнить полную оптимизацию существующего расписания. |
| F_Existing_6 | Пользователь может выполнить оптимизацию с минимизацией изменений относительно исходного расписания. |
| F_Existing_7 | При минимизации изменений сохранение исходных дня, времени, формата, аудитории и преподавателя имеет более высокий приоритет, чем остальные критерии качества. |

### 1.10. Импорт и экспорт

| Идентификатор | Требование |
|---|---|
| F_IO_1 | Система поддерживает импорт данных из `.xlsx`, `.ods`, `.csv` и `.json`. |
| F_IO_2 | Пользователь может импортировать отдельные типы данных, выбранные поля, полное состояние проекта или готовое расписание. |
| F_IO_3 | При импорте выбранных полей пользователь может сопоставить столбцы файла полям системы. |
| F_IO_4 | Система сообщает о строках, которые не могут быть импортированы из-за некорректных значений. |
| F_IO_5 | Система поддерживает экспорт расписания в `.xlsx`, `.ods`, `.csv` и `.json`. |
| F_IO_6 | Пользователь может сохранить полное состояние проекта в формате, пригодном для последующего восстановления системой. |

### 1.11. Валидация данных

| Идентификатор | Требование |
|---|---|
| F_Valid_1 | Система не принимает локально некорректные значения, включая неположительные числовые значения там, где требуется положительное число, временные интервалы с окончанием не позже начала и пароль длиной менее 6 или более 20 символов. |
| F_Valid_2 | При ошибке ввода система указывает поле и причину ошибки. |
| F_Valid_3 | Логически противоречивые, но локально корректные данные можно сохранить; их совместимость проверяется при построении или проверке расписания. |

## 2. Нефункциональные требования

| Идентификатор | Требование |
|---|---|
| NF_Limit_1 | Система не должна запускать построение или оптимизацию, если суммарное количество студентов в проекте превышает 52 646. |
| NF_Limit_2 | Система не должна запускать построение или оптимизацию, если количество преподавателей в проекте превышает 3 122. |
| NF_Limit_3 | Система не должна запускать построение или оптимизацию, если количество аудиторий в проекте превышает 15 000. |
| NF_Perf_1 | Открытие списка проектов, переход между разделами уже загруженного проекта и открытие сохранённого расписания должны завершаться не более чем за 2 секунды для 95% операций при штатной нагрузке. |
| NF_Perf_2 | После команды отмены расчёта система должна начать завершение расчёта не более чем за 2 секунды. |
| NF_Perf_3 | Во время длительного расчёта отображаемое состояние должно обновляться не реже одного раза в 2 секунды. |
| NF_Reliability_1 | Отмена расчёта или ошибка импорта не должна удалять ранее сохранённые данные проекта. |
| NF_Security_1 | Неавторизованный пользователь не должен иметь доступ к сохранённым проектам. |
| NF_Security_2 | Авторизованный пользователь не должен иметь доступ к проектам другого пользователя. |
| NF_Compat_1 | Импорт и экспорт должны сохранять русскоязычные текстовые значения без искажения символов. |
| NF_Compat_2 | Полный экспорт проекта должен быть пригоден для последующего импорта без потери поддерживаемых системой данных. |
